# Export options for Paint Pallet

For marking up a painting guide on iPad, the existing PDF already fits Procreate’s Page Assist workflow. For trying alternate colors or painting over a view, the best next export is a **layered PSD per view**, with aligned transparent PNGs as a portable option. A **UV-mapped OBJ or USDZ** is the path for rotating and painting on the model itself. Prototype it on one part of the torso before committing to the assembled kit. Procreate’s format support below is documented by the vendor. Generated Paint Pallet files were not tested on an iPad for this research. [Procreate file types](https://help.procreate.com/procreate/handbook/gallery/gallery-file-types) · [Procreate Page Assist](https://help.procreate.com/procreate/handbook/page-assist/interface) · [Procreate 3D import](https://help.procreate.com/procreate/handbook/3d-painting/import)

## Use the PDF today

In Paint Pallet, use **Project → Painting guide → Export PDF**. Transfer the PDF to iPad Files, then use **Gallery → Import** in Procreate. A single imported PDF opens in Page Assist, with each page on its own layer and in the page timeline. Procreate rasterizes the page text and vectors. For separate markup, group the imported page with a drawing layer so both appear as one page in the timeline. To share the marked-up guide again, use **Actions → Share** and select **PDF** under **Share Layers**. [Painting guide dialog](../src/renderer/guide/PaintingGuideDialog.tsx) · [Procreate PDF import](https://help.procreate.com/procreate/handbook/gallery/gallery-import-share) · [Page Assist setup and export](https://help.procreate.com/procreate/handbook/page-assist/interface) · [Layered pages](https://help.procreate.com/procreate/handbook/5.3/page-assist/organize)

Paint Pallet’s PDF includes the recipe table, four views per paint pass, and any included close-ups, installation steps, and isolated part sheets. Each view is a 1,000 × 1,000 px opaque PNG embedded into the page. The page is useful for seeing what to paint and looking up mixes. It arrives in Procreate as a single raster layer per page, so independently toggling shadows or highlights within the same view calls for a different export. ## Next export for 2D paintovers

**Layered PSD.** Export one canvas per angle, starting with Front, Back, Left and Right. Use a locked neutral model render, transparent paint layers named Shadow, Midtone, Highlight and Edge highlight when present, and a blank Paintover layer on top. Offer the viewport’s high-contrast contour shading from **Show lighting** off for the neutral layer so that bevels and ridges are easier to see when sketching over fine details. An isolated part or a close-up could use the same layout where tighter framing helps. Use **Gallery → Import** to preserve PSD layers. Inserting the same PSD into an existing artwork via **Actions → Add** flattens it. Standard raster layers and normal blending are sufficient for the first version. [Lighting-off contour shading](../src/renderer/components/Viewport3D.tsx) · [Procreate PSD file support](https://help.procreate.com/procreate/handbook/gallery/gallery-file-types) · [Procreate layer insertion](https://help.procreate.com/procreate/handbook/actions/actions-add) · [Adobe Photoshop file format specification](https://www.adobe.com/devnet-apps/photoshop/fileformatashtml/)

**Aligned PNGs.** The same render targets can produce a neutral reference plus a named RGBA PNG for each pass. They can be inserted individually into an open Procreate canvas with **Actions → Add → Insert a file**, or used in other editors. Offer a composited PNG for a quick paintover on one view. Keep identical canvas dimensions, camera and framing across the PNGs for a view. Check on iPad that blank margins are preserved through insertion and each pass lands in the right position. PSD gives users a pre-aligned stack in one import. [Procreate image insertion](https://help.procreate.com/procreate/handbook/actions/actions-add) · [Guide rendering](../src/renderer/guide/renderGuideViews.ts)

**Render changes.** Reuse the guide renderer’s orthographic cameras, assembly poses, original triangle batches and per-face recipe assignments. Generate a neutral layer plus RGBA overlays with transparent pixels outside each visible pass. All visible geometry needs to participate in depth testing, including faces outside the pass, so paint on a hidden part stays hidden. For a cumulative paintover, let shadows cover assigned faces and midtones include highlights, following the guide’s coverage rules. Stack highlights above midtones and edge highlights on top. At shared boundaries, compare the flattened result against the intended paint composite and check antialiasing for light fringes against a dark canvas. This requires dedicated render outputs beyond saving the existing opaque PNGs. [Guide render passes](../src/renderer/guide/renderGuideViews.ts) · [Face-addressed masks](../src/renderer/paint/projectMasks.ts)

**iPad validation.** Start with a candidate preset of 2,048 px square and five to seven layers per view. Try 4,096 px when the user needs closer drawing detail and the target iPad can keep the full stack. Procreate ties the maximum layer count to the iPad model’s RAM and canvas dimensions. On the intended iPad, import one PSD and confirm names, order, alpha, color, registration and that there is room for additional drawing layers. Separately insert each PNG into a matching canvas and compare it with the PSD. [Procreate layer-limit calculator](https://help.procreate.com/articles/YB7CjQ-maximum-layer-limit) · [Procreate PSD support](https://help.procreate.com/procreate/handbook/gallery/gallery-file-types)

## Palette and recipe export

Procreate imports `.swatches`, Adobe Swatch Exchange (`.ase`) and Adobe Color Swatches (`.aco`) via **Color → Palettes → + → New from file**. Start with ACO for generated palettes because Adobe publishes an RGB swatch structure and version 2 supports color names. A first device check should confirm swatch order, grouping into palettes, RGB values and whether names survive the import. A native `.swatches` file is also a supported input. The Procreate documentation cited here describes import of that format, while an encoder would require separate format validation. [Procreate palette imports](https://help.procreate.com/articles/zqbpae-importing-color-palettes) · [Adobe Color Swatches specification](https://www.adobe.com/devnet-apps/photoshop/fileformatashtml/)

Pair the palette with a **recipe CSV** for bench use. Export one row per recipe and tone with the HEX value, paint brand, bottle name and mix notes. All fields already exist in Paint Pallet. Use JSON as a machine-readable option if another tool needs stable recipe IDs and nested swatches. The palette carries digital colors. Keep the physical paint and mixing instructions in the PDF or recipe export. [Paint recipe definitions](../src/renderer/palette/types.ts) · [Existing printed recipe table](../src/main/paintingGuide.ts)

## 3D painting on the actual model

Procreate documents 3D import for **OBJ and USDZ**. Painting requires usable UVs. Partial coverage leaves unwrapped areas unpaintable, and overlapping or repeating UVs can put paint in the wrong place. For a textured OBJ, put the OBJ, its MTL, and linked images together and drag the entire folder from Files into the Gallery. Procreate documents `map_Kd` for the color map. USDZ can bundle the scene and linked textures in a single file. Both can carry color, metallic and roughness maps. Procreate can also import normal and ambient occlusion maps for reference during painting. [Procreate 3D import and texture maps](https://help.procreate.com/articles/Z0mATv-3d-painting) · [Procreate UV troubleshooting](https://help.procreate.com/articles/sCCFH-cant-paint-on-3d-model) · [OpenUSD USDZ specification](https://openusd.org/dev/spec_usdz.html)

The supplied `torso.paintproject` contains 19 binary STL parts with **13,909,724 triangles** in total, based on their embedded STL headers. The largest part has 1,217,758 triangles. The front cloth pieces have 527,332 and 489,640 triangles. This is a local file measurement. Standard STL has no texture coordinates. Paint Pallet stores assignments against original faces and its current OBJ reader extracts geometry and groups. Even a correctly textured OBJ from another app enters Paint Pallet’s mesh pipeline as triangles without texture or material data. [Binary STL structure](https://www.loc.gov/preservation/digital/formats/fdd/fdd000505.shtml) · [Paint masks](../src/renderer/paint/projectMasks.ts) · [OBJ parser](../src/shared/textMesh.ts) · [Project archive](../src/main/projectArchive.ts)

A paintable export would need a separate mesh and texture pipeline:

1. **Build a lighter copy of the selected parts.** Preserve names, poses, the silhouette and the surface details needed to place paint. Reuse the original triangles and face IDs as the source for baking. Paint Pallet’s existing meshoptimizer preview is worth evaluating as a candidate for geometry. It was built for camera navigation, so its fidelity at paint boundaries and thin parts needs testing. [Current mesh and preview design](../PLAN.md)
2. **Generate UVs and bake the color map.** Make non-overlapping UV islands with padded seams. Project the committed recipe colors and tone/edge assignments from the original mesh into the simplified mesh’s UV texture. Keep projection part-local so closely spaced cloth, armor or joints cannot pick up colors from their neighbors. Keep baked color distinct from any reference normal or occlusion maps to avoid baking the viewer’s lighting into the color. xatlas is one library to evaluate for UV generation. For a geometry-only test of the Procreate painting experience, an STL part unwrapped in Blender is enough. Bringing existing Paint Pallet colors along still needs a bake. [xatlas UV generation](https://github.com/jpcy/xatlas) · [Blender UV tools](https://docs.blender.org/manual/en/5.0/modeling/meshes/editing/uv.html) · [Procreate 3D materials](https://help.procreate.com/articles/Xo46s-3d-materials-in-procreate)
3. **Validate OBJ first, then package the same asset as USDZ.** Begin with a single front cloth part at 2K, then test a small assembled subset before trying the whole torso. Check import time, rotation, color placement, brush strokes across UV seams, thin edges, neighboring parts, and the ability to select each intended mesh. Compare one shared atlas with splitting selected parts into a small number of texture sets. Procreate documents multiple texture sets and states that textures above 2K require at least 4 GB RAM. Its device guidance cites polygon count as a factor without publishing a universal ceiling. The torso’s importability, useful triangle count and practical number of texture sets need measurements on the target iPad. [Procreate texture sets](https://help.procreate.com/procreate/handbook/5.3/3d-painting/layers) · [Procreate iPad 3D limits](https://help.procreate.com/articles/J24zu-ipads-compatible-with-3d-painting) · [OpenUSD USDZ packaging](https://openusd.org/dev/spec_usdz.html)

### Bring iPad work back

Procreate can share a painted model as OBJ or USDZ, or export its texture sets as flattened PNGs per material channel. A practical first return path is to use those files as reference outside Paint Pallet. A future texture importer could accept the exported color PNGs against unchanged UVs and match them to the original export using a manifest with mesh, part and texture-set IDs. Turning pixels back into editable Paint Pallet recipe assignments would need explicit projection and recipe mapping. Freehand gradients can span many original faces, and the current OBJ import reads geometry only. For 2D work, an exported paintover image could be used through the existing reference-image workflow. ## Other export destinations

| Format | Best use | Paint Pallet considerations |
| --- | --- | --- |
| **glTF / GLB** | Rotatable color preview for a web viewer or a 3D tool. | GLB can embed textures and carry part transforms. A color preview can use per-face colors encoded as vertex colors with vertex splits at color boundaries, or reuse the baked textures from the 3D painting pipeline. Procreate lists OBJ and USDZ for direct 3D import. [Khronos glTF specification](https://registry.khronos.org/glTF/specs/2.0/glTF-2.0.html) · [Procreate file types](https://help.procreate.com/procreate/handbook/gallery/gallery-file-types) |
| **3MF** | Transfer an assembled model to an identified slicer or a color-capable print workflow. | The core format can express units and components. Its Materials and Properties extension defines colors and textures. Test whether the target slicer reads the selected extension and preserves the intended colors. Procreate lists OBJ and USDZ for direct 3D import. [3MF Consortium specifications](https://3mf.io/spec/) · [Procreate file types](https://help.procreate.com/procreate/handbook/gallery/gallery-file-types) |
| **STL** | Export geometry for a slicer when paint appearance is unnecessary. | Standard STL carries the triangular surface. The existing archive already stores original source meshes and paint assignments for Paint Pallet’s own workflow. [Binary STL structure](https://www.loc.gov/preservation/digital/formats/fdd/fdd000505.shtml) · [Project archive](../src/main/projectArchive.ts) |

For the iPad workflow, use PDF now for bench notes, then build the PSD and PNG exports together around the same render passes. Add the palette and recipe CSV when matching digital colors to bottle paints is the goal. If direct painting on the model is the priority, run the single-cloth OBJ test before investing in whole-kit 3D export.
